An inbound AI concierge for a home services business

A caller phones a heating and air conditioning company about replacing a furnace. An AI agent asks for the service address, reads it back, saves the lead to a customer profile, and hangs up after saying goodbye. Sentiment is scored on every utterance and the lead is qualified when the call ends. This page shows how the pieces connect and what happens on one call, hop by hop.

01

System architecture

Four groups do the work. The caller is on an ordinary phone. Twilio carries the call and owns three Conversations services: the Orchestrator, which records every utterance into one conversation per customer; Memory, which holds the customer profile; and Intelligence, which runs language operators over the conversation. The application in the middle runs the agent loop on the Twilio Agent Connect SDK, and calls OpenAI for the model. Audio never reaches the application. ConversationRelay converts speech to text and text to speech, and the application only ever exchanges text with it over a WebSocket.

Caller

What
A homeowner on any phone, calling or texting one US local number.
Why here
The caller's phone number is the identifier that ties a call, a text and a returning caller to one customer profile.
Talks to
The Twilio number over the PSTN, for voice and SMS.
Constraint
SMS from a US local number needs an approved A2P 10DLC campaign. The demo number sits in a Messaging Service that already has one.

ConversationRelay

What
The <ConversationRelay> TwiML noun. Twilio transcribes the caller, sends each finished utterance to a WebSocket as a prompt message, and speaks the text tokens the application streams back.
Why here
It removes audio handling from the application entirely. Speech-to-text, text-to-speech, barge-in detection and endpointing are all Twilio's, and each is a TwiML attribute the demo's TwiML builder can change per call.
Talks to
The application's /twiml webhook once per call and its /ws WebSocket for the rest of it. With conversationConfiguration set, it also writes the transcript into the Orchestrator.
Constraint
One session per call. Interrupt messages report what the caller had heard when they barged in, which the application has to use to rewrite its own chat history.

Conversation Orchestrator

What
A conversation configuration that groups communications by customer profile. Every voice utterance, agent reply and text message lands in one conversation.
Why here
It is the join between channels and the trigger for Intelligence. Memory resolves the caller to a profile through it, and Intelligence rules fire on its events.
Talks to
ConversationRelay for voice, capture rules on the number for SMS, Memory for the profile, Intelligence for rule execution, and the application's /webhook for conversation events.
Constraint
A conversation stays open until it is closed or times out. End-of-call rules do not fire until it closes.

Conversation Memory

What
A memory store with the default Contact trait group and a custom HvacService group: reason for calling, service type, service address, address confirmed, purchase interest and its rationale, urgency, last call.
Why here
The agent reads the profile at the start of a call, so a returning caller is not asked for their address twice, and the business reads it afterwards as the lead record.
Talks to
The Orchestrator, which resolves the caller's phone number to a profile; the application, which reads and patches traits; Intelligence, which reads the profile as operator context.
Constraint
A trait can only be written if it is declared in the store's trait group schema first.

Conversation Intelligence

What
An intelligence configuration with two rules. Rule one runs Twilio's Sentiment operator on every communication. Rule two runs Summary, Sentiment and a custom HVAC Lead Qualification operator when the conversation closes.
Why here
It gives the business an independent read of the call. The lead operator judges purchase interest from the whole transcript, which the agent is never asked to do mid-call.
Talks to
The Orchestrator for triggers and transcript, Memory for context, and the application's /webhooks/intelligence for results.
Constraint
Per-utterance results arrive a few seconds after the utterance. End-of-call results arrive a few seconds after the conversation closes, not after the caller hangs up.

Agent server on Twilio Agent Connect

What
A Node service built on the twilio-agent-connect SDK. The SDK answers the webhooks, validates Twilio signatures, runs the ConversationRelay WebSocket, and looks up the conversation and profile for each call. The application adds the agent turn, two tools, and the Intelligence webhook.
Why here
It is the only part you build. Everything about carrying the call is the platform's; everything about what the agent says and remembers is here.
Talks to
ConversationRelay, OpenAI, Memory and the Orchestrator through REST, and the web console.
Constraint
Needs a public HTTPS and WSS hostname that Twilio can reach.

Call records, prompts and TwiML presets

What
One JSON file: every call's transcript, tool calls, latency and Intelligence results; versioned system prompts; named sets of ConversationRelay attributes.
Why here
It lets the demo change the prompt or the voice between calls and compare the results, without redeploying.
Talks to
The agent server only.
Constraint
A demo store for a handful of users, not a database.

Web console

What
A single-page app with four tabs: a live view of the current call, call history, a prompt editor and a TwiML builder with a live preview.
Why here
It makes each product's contribution visible while a call is in progress: the transcript, the sentiment, the profile filling in, and the post-call results.
Talks to
The agent server's JSON API and its server-sent event stream. Each call links out to Voice Insights in the Twilio Console.
Constraint
Shows latency measured by the application only. Speech-to-text, text-to-speech and network time per turn are in Voice Insights.

OpenAI, through the Agents SDK

What
The model, called through the OpenAI Agents SDK with streaming and two tools: save_customer_details and end_call.
Why here
The customer's own LLM. Agent Connect is model-agnostic; this demo uses OpenAI because that is what the customer runs.
Talks to
The agent server only.
Constraint
Time to first token is most of the caller's perceived wait. Tool calls add a second model round trip to the turn they happen in.

Call flows

Two flows cover the demo. The first is the scenario under test, an inbound call from a customer who wants a furnace replaced. The second is a text to the same number, which lands in the same conversation and profile. Each hop names who sends what to whom.

Flow A. An inbound call, from greeting to post-call intelligence

The scenario under test: the caller wants a replacement, the agent needs the service address, confirms it, saves the lead and hangs up.

Caller
ConversationRelay
Agent server
OpenAI
Orchestrator, Memory, Intelligence

The call reaches the Twilio number, whose voice URL is the agent server's /twiml endpoint. Twilio posts the call's details there, signed with X-Twilio-Signature.

The agent server validates the signature before it answers. A request without a valid signature gets a 403.

The SDK calls the application's inbound customizer, which creates a call record and returns the active TwiML preset: voice, speech-to-text provider and model, greeting, interruption settings and hints. The SDK adds the WebSocket URL, the <Connect action> URL and conversationConfiguration, and returns the TwiML.

conversationConfiguration is what puts the call into the Orchestrator. No voice capture rule is needed, and adding one would start a second transcription.

ConversationRelay creates or resolves a conversation under the configuration at call connect, with two participants: the caller as CUSTOMER and the Twilio number as AGENT. Memory then resolves the customer's phone number against the phone trait, finding an existing profile or creating one.

Profile resolution is asynchronous and best effort. The participant exists before its profileId does, and a failed lookup leaves it null without failing the call. Only a participant explicitly typed CUSTOMER gets a new profile created, which ConversationRelay does for the caller.

ConversationRelay opens the WebSocket and sends setup with the CallSid. It speaks the welcome greeting from the TwiML while the SDK polls the Orchestrator for the conversation and its profile in the background.

The lookup overlaps the greeting, so the first turn does not wait for it.

ConversationRelay transcribes the utterance and sends a prompt message. The SDK fetches the caller's memory once for the call and hands the text, the memory and the session to the application's turn handler.

Memory is fetched once per call rather than on every turn, which keeps a network round trip off the hot path.

The application composes the active system prompt with the caller's profile and recent summaries, appends the utterance to the conversation's chat history, and runs the agent with streaming on.

Time to first token is the caller's wait. The application records it on every turn and shows it in call history.

Each token goes to ConversationRelay as a text message as soon as it arrives, after a filter that spells five-digit numbers digit by digit so a ZIP code is not read as a quantity. ConversationRelay starts speaking before the reply is complete.

The filter holds back a trailing run of digits until it is complete, because a ZIP code can arrive split across tokens.

Each caller turn and each agent reply becomes a communication in the conversation. Intelligence rule one runs Sentiment on each and posts the result to /webhooks/intelligence, where the application matches it to the call by CallSid and streams it to the live view.

On a measured demo call, 23 communications alternated caller and agent, one per whole turn, not one per streamed token. Results land one to four seconds after the turn.

The prompt makes the agent ask for the service address, read it back and wait for a yes. On confirmation the model calls save_customer_details, and the application patches the profile's Contact and HvacService traits.

The tool takes an addressConfirmed flag. A model told to save only after confirmation still needs a field that records whether it did.

If the caller talks over the agent, ConversationRelay stops speaking and sends interrupt with the text spoken so far. The SDK cancels the stream, and the application truncates the stored reply to that text.

Without the truncation, the model believes the caller heard the whole reply and answers questions the caller never asked.

When the caller is done, the model says goodbye and calls end_call in the same turn. After the goodbye has streamed, the application waits for its estimated speaking time plus a second and a half, then ends the call through the Calls REST API.

A timer, not an event. ConversationRelay can report when the agent stops speaking, but the SDK version used does not pass those events to the application.

With the voice channel's statusTimeouts left null, the conversation closes when ConversationRelay's transcription stream ends. The application also sets it to CLOSED through the API as soon as the WebSocket drops.

Closing is what fires the end-of-call rule. Voice timers run on transcription events, not call events, so a call in which nobody speaks stays ACTIVE indefinitely. The explicit close covers that case.

Rule two runs Summary, Sentiment and HVAC Lead Qualification and posts all three to the same webhook. The application writes the lead result's purchase interest and rationale to the profile, and fills in address and reason only if the agent never saved them.

Purchase interest is judged from the whole transcript by an operator, not by the agent mid-call.

Flow B. A text message to the same number

Same agent, same profile, same conversation history. The reply is returned whole instead of streamed.

Caller
ConversationRelay
Agent server
OpenAI
Orchestrator, Memory, Intelligence

Two capture rules on the configuration, from any address to the number and from the number to any address, put the inbound text into the customer's conversation. Memory resolves the same profile a call from that phone would.

The outbound rule is what threads the agent's reply into the same conversation.

The configuration's status callback posts the new communication to /webhook. The SDK's SMS channel fetches memory for the message and hands it to the application.

SMS fetches memory on every message, because a text thread has no call boundary to cache against.

The same prompt and tools as voice, with a note that the channel is text, so replies can run longer. The reply is generated whole rather than streamed.

The end-call tool is not offered on SMS.

The application returns the reply text and the SDK sends it as an SMS from the number. The outbound capture rule records it in the conversation.

The conversation closes on the configuration's five-minute timeout, which fires the same end-of-call rule as a phone call.

03

Setting this up in your own Twilio account, voice only

The demo provisions everything with one script, but every step below can be done in the Console or the REST API, and the order matters. Each object refers to the one before it by ID: a conversation configuration names its memory store and its intelligence configurations, a rule names its operators, and the TwiML names the conversation configuration. Build from the bottom of that chain up and nothing has to be edited twice. Messaging is out of scope here; it adds capture rules and a status callback to the same configuration and is covered separately.

Each arrow is an ID or URL the next object needs. Steps marked async return a status URL to poll before the object can be used.

STEP 01

Accept the AI/ML addendum and create a standard API key

Console, once per account

ConversationRelay, the Orchestrator, Memory and Intelligence are all subject to the Predictive and Generative AI/ML Features Addendum. In the Console, open Voice > Settings > Privacy & Security, accept it, and save. The ConversationRelay documentation lists it as a prerequisite to using the noun at all.

Create a standard API key under API keys & tokens. The Conversations APIs take the key SID and secret as Basic auth; the Agent Connect SDK also needs the account's Auth Token to validate webhook signatures.

ConversationRelay onboardingAgent Connect quickstart

Key type matters. The Agent Connect quickstart specifies a standard key. A restricted key works only for the resources it was granted and fails elsewhere with an authorization error, so prove a key against an endpoint it covers before debugging anything else.

STEP 02

Create the memory store

Memory API or Console

The store holds customer profiles and the identity rules that match a caller to one. Create it first, because the conversation configuration names it and cannot resolve profiles without it.

POST https://memory.twilio.com/v1/ControlPlane/Stores
{ "displayName": "hvac-concierge-memory", "description": "HVAC concierge demo" }
# 202 Accepted: { "message": ..., "statusUrl": ... }

The create is asynchronous and the response carries no store ID. Poll the statusUrl until it completes, then list stores and match on displayName to get the mem_store_ ID. A new store comes with a Contact trait group and identity rules for phone, email and chat. The phone rule is what links a caller's number to a profile.

STEP 03

Declare the traits you will write

Memory API or Console

Memory accepts only traits that are declared in one of the store's trait groups. The default Contact group already covers name, phone and street address. Anything specific to the business goes in a new group before the application tries to write it.

POST https://memory.twilio.com/v1/ControlPlane/Stores/{storeId}/TraitGroups
{ "displayName": "HvacService",
  "traits": {
    "reasonForCalling": { "dataType": "STRING" },
    "serviceAddress":   { "dataType": "STRING" },
    "addressConfirmed": { "dataType": "BOOLEAN" },
    "purchaseInterest": { "dataType": "STRING" } } }
Create a trait groupPatch profile traits

Plan groups before you create them. A trait cannot be moved from one group to another later, and dataType values are uppercase.

STEP 04

Create any custom language operators

Intelligence API or Console

Twilio-authored operators such as Sentiment and Summary already exist on every account; list them to get their IDs. A custom operator is a prompt plus an output format. The demo's lead qualification operator returns JSON against a schema, with Memory context enabled so it can see the customer profile.

POST https://intelligence.twilio.com/v3/ControlPlane/Operators
{ "displayName": "HVAC Lead Qualification", "author": "SELF",
  "outputFormat": "JSON", "outputSchema": { "type": "object", "properties": { ... } },
  "prompt": "You analyze a phone call ...",
  "context": { "memory": { "enabled": true } } }
Create custom operators

Schema limits. The output schema is a structured-output schema: no minLength, no pattern, and no nullable enums. Use an explicit value such as UNKNOWN for absence.

STEP 05

Create the intelligence configuration and its rules

Intelligence API or Console

An intelligence configuration is a list of rules, and each rule is a trigger, up to five operators, optional context and a webhook action. The demo uses two:

  • Live: trigger COMMUNICATION with count: 1, operator Sentiment. Fires on every turn.
  • Post-call: trigger CONVERSATION_END, operators Summary, Sentiment and Lead Qualification, Memory context on.

Both post to the application's /webhooks/intelligence. The payload carries the conversation ID, each operator's result, and reference IDs that include the CallSid, which is how the application matches a result to a call.

Create an intelligence configurationDefine rulesRule execution webhook

The webhook URL is fixed at creation. Create the configuration with the application's final public hostname, or update it once the hostname is known. Updates are a full replacement of the rules list.

STEP 06

Create the conversation configuration

Conversations API or Console

This is the object the call is routed into, and it ties the others together.

POST https://conversations.twilio.com/v2/ControlPlane/Configurations
{ "displayName": "hvac-concierge",
  "conversationGroupingType": "GROUP_BY_PROFILE",
  "memoryStoreId": "mem_store_...",
  "intelligenceConfigurationIds": [ "intelligence_configuration_..." ],
  "channelSettings": { "VOICE": { "captureRules": [] } } }
# 202 Accepted: poll statusUrl, then list configurations and match displayName
  • Grouping: GROUP_BY_PROFILE keeps a customer's calls, and later their texts, in one conversation. It cannot be changed after creation.
  • No voice capture rules. With ConversationRelay the call joins the conversation through the TwiML in step 8. A capture rule on the same number starts a second transcription and bills speech-to-text twice.
  • Voice timeouts left null. The conversation then closes when the call's transcription stream ends, which fires the CONVERSATION_END rule.

The Orchestrator quickstart is written for passive capture. Its Console steps tick Set up automatic capture on the voice number. For a ConversationRelay number, leave that box clear, or remove the rule afterwards.

STEP 07

Run the agent server on a public hostname

Your infrastructure

Twilio has to reach the application over HTTPS for the TwiML webhook and over WSS for the ConversationRelay socket. The Agent Connect SDK reads its configuration from environment variables:

TWILIO_ACCOUNT_SID   TWILIO_AUTH_TOKEN   TWILIO_API_KEY   TWILIO_API_SECRET
TWILIO_PHONE_NUMBER
TWILIO_CONVERSATION_CONFIGURATION_ID   # from step 6
TWILIO_VOICE_PUBLIC_DOMAIN             # hostname only, no https://

On startup the SDK reads the conversation configuration to learn its memory store, so the store ID does not need its own variable. It serves /twiml, the /ws WebSocket, the <Connect action> callback and the call status callback, and validates the Twilio signature on each.

Agent Connect quickstartWebSocket messages

Signature validation depends on the public URL. Behind a proxy, the SDK rebuilds the URL from X-Forwarded-Proto and X-Forwarded-Host. If the proxy rewrites either, every webhook is rejected with a 403.

STEP 08

Point the phone number at the application

Console or Phone Numbers API

Set the number's voice URL to https://your-host/twiml with method POST. The SDK answers with TwiML along these lines, which is the step that puts the call into the conversation configuration:

<Response>
  <Connect action="https://your-host/conversation-relay-callback">
    <ConversationRelay url="wss://your-host/ws"
      conversationConfiguration="conv_configuration_..."
      welcomeGreeting="Thanks for calling ..."
      ttsProvider="ElevenLabs" transcriptionProvider="Deepgram" />
  </Connect>
</Response>

conversationConfiguration creates or resolves a conversation through the grouping rules. Passing conversationId instead joins a specific existing conversation and bypasses grouping, which is how a later handoff to a human keeps the whole call in one conversation.

STEP 09

Test without a phone call, then with one

Verification
  • Signed webhook first. Send a simulated, signed voice webhook to /twiml and confirm a 200 with the expected TwiML. This proves the hostname, the signature check and the configuration ID without placing a billed call.
  • One real call. Then list conversations under the configuration. Expect one conversation with two participants, the caller as CUSTOMER with a profileId and the number as AGENT, and one communication per turn.
  • After hang-up. The conversation should read CLOSED, and the post-call operator results should reach the webhook within seconds.
How profiles resolveConversationRelay call summary

A missing profileId is not always an error. Resolution runs asynchronously and best effort, so it can appear a moment after the participant does. It stays null for good only if resolution failed or the participant is not a customer.

05

Design choices worth teaching

The application never handles audio. ConversationRelay owns speech-to-text, text-to-speech, endpointing and barge-in. The application's contract with it is text over a WebSocket, and every speech setting is a TwiML attribute. That is why the demo can expose a TwiML builder: changing the voice, the transcription model or the interruption sensitivity is a configuration change, not a code change.

Stream the reply, and measure the first token. The caller's wait is the time from the end of their speech to the start of the agent's. Streaming tokens into ConversationRelay lets speech start on the first sentence. The application measures time to first token on its side; Voice Insights adds the speech-to-text, text-to-speech and network legs from Twilio's side, and every call in the console links to it.

Facts from the agent, judgement from Intelligence. The agent's tool saves what the caller stated: name, confirmed address, reason, service type. Purchase interest is a judgement about the whole call, so it comes from a language operator that reads the full transcript after the conversation closes. The two writes go to the same profile from different sources, and the console shows both.

Close the conversation on hang-up. End-of-call Intelligence runs when the conversation closes, not when the call ends. With voice timeouts left null the conversation closes when the transcription stream ends; the application also closes it as soon as the WebSocket drops, because voice timers run on transcription events and a silent call would otherwise stay open.

Rewrite history on barge-in. When the caller interrupts, the chat history is truncated to what they actually heard. Skipping this step is the most common cause of a voice agent answering a question nobody asked.

Spell numbers in code, not only in the prompt. The prompt asks for ZIP codes digit by digit, and a stream filter enforces it, because a model instruction alone is not reliable and text-to-speech engines read five-digit numbers as quantities.

06

Open items

Each of these was observed in the demo or read from documentation, but not confirmed as platform behaviour.

  • Hang-up timing is an estimate. The application waits for roughly 2.6 words per second of goodbye plus 1.5 seconds. A slower voice or a longer goodbye can be cut off, and a fast one leaves a pause. ConversationRelay's speaker-events subscription would give an exact end-of-speech signal; using it needs a version of the Agent Connect SDK that forwards those messages.
  • How quickly a closed conversation fires its end-of-call rule. In a related build, results arrived about two seconds after an explicit close on one call and about four and a half minutes later on another, where the conversation stayed active after the hang-up. The demo closes explicitly to avoid the second case.
  • How many communications a voice turn produces. The lifecycle documentation warns that a COMMUNICATION trigger fires per text-to-speech fragment. On a measured demo call with streamed replies, each agent turn was one communication. Whether that holds for every reply shape, such as a reply split by an interruption, is not confirmed.
  • Reasoning effort on the model. The demo runs the model at low reasoning effort. With reasoning off, the agent skipped the address question and saved details before the caller confirmed them. Whether a faster setting holds up with a stricter prompt is untested.
  • Profile resolution on the first utterance. The documentation states that resolution is asynchronous and best effort, so on a first-time caller the profile can be missing for the opening seconds of the call. The agent's save tool reports that rather than failing silently, but the window has not been measured.
  • Which Console path holds the addendum. The ConversationRelay onboarding guide gives Voice > Settings > Privacy & Security for the current Console and Voice > Settings > General for the legacy one. Console navigation moves; search for the addendum by name if neither path matches.

Deliberately absent

No pricing appears on this page, and no account identifiers, phone numbers or customer names. The business in the scenario is invented. Twilio list prices are negotiated per account and they move, so the Twilio pricing pages carry the current figures.
